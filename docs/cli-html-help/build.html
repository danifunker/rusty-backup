rb-cli build

Build a disk in one step: a partition table with each partition formatted, filled from an image or left empty, or one bare volume; to an image file or a device (`--yes`). The command-line form of the Build Disk tab: `build disk.img --size 2G --table mbr --partition 512M --partition rest --format 1=fat:DOS --format 2=ext4`

Usage

Usage: build [OPTIONS] <TARGET>

Arguments

<TARGET>
The image file to create, or a device path (`/dev/sdX`, `/dev/diskN`, `\\.\PhysicalDriveN`) to build on. A device needs `--yes` and is built at its own size

Options

--size
Disk (or volume) size for an image target, e.g. `64M`, `2G`. Ignored for a device and for a fixed-geometry volume
--table
Partition table to write. Leave it out for one bare volume (give `--fs`)
--partition
A partition, in disk order: `SIZE[:TYPE[:NAME]]`, where SIZE is `20M` / `1G` / bytes or `rest`, and TYPE is the table's own type value (MBR byte, GPT GUID, `Apple_HFS`, `DOS\3`, ...). Repeat for each partition; the default is one `rest` partition
--format
Format partition N blank: `N=FS[:LABEL]`, where FS is a `new volume` / `new floppy` filesystem name (`fat`, `hfs`, `pfs3`, `ufs-solaris`, ...). The partition's type follows the filesystem unless the `--partition` spec gave one
--fill
Pour an image into partition N after the table is written: `N=PATH`. Any image Rusty Backup can read works
--bootable
Mark partition N bootable: the MBR active flag (one partition) or the RDB bootable flag. Repeatable on RDB
--filesystem
Embed an Amiga filesystem handler in the RDB, `DOSTYPE=PATH` (repeatable). PATH is the handler's AmigaDOS load file (`L:PFS3`, `L:SmartFilesystem`); without one, a DosType the ROM lacks cannot mount unaided
--mac-driver
The Mac driver on an APM disk: `bundled` (the default: a donor's own driver if it has one, otherwise Apple SCSI 7.3.5), `none`, or the path of an Apple-formatted disk to take the driver from. The driver serves SCSI; a Mac with the disk on IDE won't mount it
--align
Partition-start alignment, e.g. `1M` or `63s`; blank uses the table's default
--heads
Heads for the cylinder-aligned tables (SGI, RDB, Sun, NeXT, Solaris x86)
--sectors
Sectors per track for the cylinder-aligned tables
--fs
With no `--table`: the filesystem of the one bare volume
--from
Start from this disk image's layout: its table, special partitions and their contents, at the new `--size`. Each partition is copied unless `--format N=FS` or `--empty N` says otherwise; `--partition SIZE` sets the sizes in order. A copied filesystem that can resize grows to its partition; one that can't keeps its size. A label (SGI, Sun, NeXT, RDB, AHDI, X68000) keeps its head region verbatim, resized for the new disk
--empty
With `--from`: leave partition N empty instead of copying it
--preset
Build a fixed bootable preset instead of a table or a volume: `x68k` (IPL, X68000 table, Human68k) or `sgi-efs` (volume header, EFS root). The same disks `new hd x68k` / `new hd sgi-efs` make
--scsi
`--preset x68k`: write the SCSI form (1024-byte sectors) rather than SASI
--x68k-partitions
`--preset x68k`: how many Human68k partitions, 1 to 8
--system-disk
`--preset x68k`: a Human68k system floppy cloned into partition 1
--label
With no `--table`: the volume label
--geometry
With no `--table`: the fixed geometry of a floppy format, e.g. `d71` for a 1571 disk (`cbm`), `80` tracks (`dfs`, `rsdos`), `80ds` (`dragondos`). The default is the format's first
--ntfs-version
The on-disk version of every NTFS volume or partition this builds: `1.2` (alias `nt4`) for Windows NT 3.5 / 3.51 / 4.0, `3.1` (alias `xp`, the default)
--container
Container to encode an image target into: raw, vhd, vhd-dynamic, qcow2, vmdk, chd, 2mg, dc42, woz or moof. Defaults to the one the target's extension names (`.chd`, `.vhd`, ...), else raw
--force
Overwrite an existing image file
--yes
Required to build on a device; everything on it is erased
